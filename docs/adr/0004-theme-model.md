# 主题模型：今日主题压在固定主题之上，内置词用覆盖式修改

新增"指定当天主题 + 主题增删改查"时，主题从单一概念扩张成五个（内置、自定义、今日、固定、停用），必须先把它们的关系钉死，否则后续每加一个入口都要重新解释一遍。

**决策**

1. **今日主题是独立概念，不是"固定主题的临时值"**。它只对当天生效、优先于固定主题、跨天自动失效、不提供手动清除。理由：临时指定不该破坏长期设置；自动失效省掉了"忘记恢复"的清理逻辑。
2. **内置词可改，但改动以覆盖形式存进配置**（`themeOverrides`，按原始搜索标签定位），内置默认值仍写死在代码里，因此可一键恢复，升级程序也不会冲突。
3. **停用是标记，不是删除**。内置词只能停用（可恢复）；自定义词才可删除。删除正在使用的主题时提示并自动退回随机。
4. **中文名到英文标签**：内置词典优先（直接映射到 wallhaven 真实存在的标签）→ 在线翻译兜底（MyMemory）→ 结果放进可编辑框让人确认。机器翻译会给出「The pussy cats」这类没法搜的结果，所以必须清洗并允许手改。
5. **保存前试搜验证**；网络不可用时允许保存但标记为「未验证」，联网后补验。禁止离线保存会让"代理一挂就改不了主题"。

**Considered**: 把今日主题实现成"固定主题的临时值"（破坏长期设置、跨天要清理）；允许直接编辑内置词表（升级丢失修改）；离线一律禁止保存（可用性差、与"兼容无法请求"的初衷冲突）。

**Consequences**: `config` 多了 `themeOverrides`、`disabledWords`、`todayTheme(date/display/query)` 三组字段；主题池的计算收敛在 `ThemeCatalog.All/Pool` 一处，UI 必须能区分「内置 / 自定义 / 已修改 / 未验证 / 已停用」五种状态；试搜会消耗 wallhaven 配额（45 次/分钟，日常够用）。
